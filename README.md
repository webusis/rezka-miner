# rezka-miner

Клиент и API для одного онлайн-кинотеатра: поиск, структура тайтла
(переводы → сезоны → серии → качества), прямые ссылки на поток и просмотр
на старом Android-планшете (4.2.2, API 17, armeabi-v7a).

Сайт-источник отдаёт разметку только браузеру (антибот с proof-of-work),
поэтому есть две независимые сборки одного и того же API:

* **на планшете** — `apk-server/`: python2-сервер прямо в APK, сам поднимает
  `:8080`, сам решает proof-of-work, без браузера, без рута и **без хоста**.
  Это основной режим: поставил APK — и оно живёт само.
* **на хосте** — `agent.js` (node + playwright держит браузерную сессию живой)
  плюс `server.py`, который ходит к сайту через неё. Нужен для разработки,
  отладки и если хочется смотреть с компьютера.

Плюс отдельная вкладка YouTube: ленты через официальный YouTube Data API,
воспроизведение через yt-dlp — всё локально в chroot планшета (`chroot/`).

## Схема

Планшет — самодостаточная сборка, хост ей не нужен:

```
планшет (android 4.2.2)
┌──────────────────────────────────────────┐
│ di.rezka (java-клиент)                   │
│   └─> 127.0.0.1:8080  RezkaServer.apk    │
│        ├─ python2-сервер: поиск, структура│
│        ├─ резка: urllib + PoW, прокси     │
│        │  видео/картинок (http + Range)   │
│        └─ /api/yt/* ──> chroot debian     │
│                        yt_service.py :8081│
│                        Data API + yt-dlp  │
└──────────────────────────────────────────┘
```

Хост — вторая, необязательная сборка того же API (разработка, просмотр с компа):

```
хост (linux)
┌──────────────────────────────┐
│ agent.js :9333               │
│   playwright + живая сессия  │
│        ▲                     │
│ server.py :8080 ─── /api/*   │
│   web/ — фронт               │
└──────────────────────────────┘
```

## Планшет без хоста

`apk-server/` — тот же API, но на python2 внутри APK. Поднимает `0.0.0.0:8080`
сам, решает антибот-челлендж сам, кэша на диске не требует. Хосту с ним
разговаривать не о чем: смотреть можно с самого планшета (`127.0.0.1:8080`)
или с любого устройства в сети (`<ip-планшета>:8080`).

## Быстрый старт на хосте

```bash
npm install                 # playwright
npx playwright install chromium
node agent.js               # держит сессию, :9333
python3 server.py           # API + веб, :8080
```

Открыть `http://127.0.0.1:8080` — там одностраничный фронт.
Сервер собирает ссылки сам, кэширует ответы в `data/cache` (1 час).

Без node-агента тоже работает, если запустить сервер с
`REZKA_CURL=1 python3 server.py` — тогда используется чистый urllib-клиент
(`rezka_curl.py`) с ручным решением челленджа. Медленнее, зато без браузера.

## API

| Маршрут | Что отдаёт |
|---|---|
| `GET /api/search?q=слово` | карточки поиска (id, url, title, poster, type, info) |
| `GET /api/title?url=...&streams=1` | полная структура: переводы, сезоны, серии, качества |
| `GET /api/stream?id=&tid=&season=&episode=` | качества одной серии (ленивая подгрузка) |
| `GET /api/stream_proxy?url=` | прокси видео/картинок: наружу https, планшету http + Range |
| `GET /api/playlist?url=&season=` | m3u-плейлист сезона (лучшее качество) для MX Player |
| `GET /api/v/<id>.mp4` | короткая ссылка на серию (MX Player не любит длинный query) |
| `GET /api/yt/search?q=`, `/recs`, `/subs`, `/channel?cid=`, `/playlist?list=` | ленты YouTube |
| `GET /api/yt/stream?vid=` | прокси mpegts-потока видео |

У автономного сервера на планшете (`apk-server/`) набор свой: есть
`/api/new` (свежее), `/api/season`, `/api/log/*` — и он же проксирует
`/api/yt/*` в chroot.

`/api/title`:

```json
{
  "id": 64703, "url": "...", "title": "...", "poster": "...",
  "type": "series",
  "translators": [
    {
      "id": 111, "name": "Студия 1", "active": true,
      "seasons": [
        { "season": 1, "title": "1 сезон",
          "episodes": [
            { "episode": 1, "title": "...",
              "qualities": { "360p": "https://...", "720p": "...", "1080p": "..." } }
          ] }
      ]
    }
  ]
}
```

Премиум-переводы и премиум-качества (2K/4K) отфильтровываются. Ссылки
собираются только для активного перевода, у остальных — структура, качества
подгружаются по клику.

## Клиенты

| Клиент | Где | Что это |
|---|---|---|
| веб | `web/` | одна страница, отдаётся сервером; ничего собирать не надо |
| `di.rezka` | `app/` | Java-клиент: поиск, структура, диалог качества, запуск в MX Player |
| `RezkaConsole` | `console/` | консоль/терминал на планшете (нативная PTY через jni) |
| `RezkaServer` | `apk-server/` | python2-сервер для автономного режима, ставится на планшет |

Клиенты получают постеры и видео через `/api/stream_proxy`, чтобы старый
планшет не давился https: наружу сервер ходит по TLS 1.2, планшету отдаёт
обычный http + `Range`.

## Планшет

1. Собрать (или взять готовый из `web/`) `RezkaServer.apk` и `di.rezka`,
   поставить оба.
2. В приложении один раз указать адрес сервера. Если сервер поднят на самом
   планшете — `http://127.0.0.1:8080`.
3. Видео открывается в MX Player Pro: по серии или плейлистом на сезон.

Сборка APK — без gradle и IDE: `aapt2 → javac → d8 → zipalign → apksigner`.

```bash
mkdir -p android && cd android
curl -O https://dl.google.com/android/repository/build-tools_r34-linux.zip
curl -O https://dl.google.com/android/repository/android-17_r03.zip
unzip build-tools_r34-linux.zip     # android-14: aapt2, d8, apksigner, zipalign
unzip android-17_r03.zip            # android-4.2.2: android.jar
cd ../app && ./build.sh             # -> app/Rezka.apk
cd ../console && ./build.sh         # -> console/RezkaConsole.apk (нужен gcc-arm-linux-gnueabi)
```

`apk-server/` собирается python-for-android (python2 + openssl), подробности —
`apk-server/README.md`. Установка сервера и хука автозапуска на прошивке —
`chroot/README.md`, там же грабли конкретной модели планшета.

Автономный режим (сервер на планшете, без хоста) собран вокруг того, что
python2 на Android 4.2.2 не имеет системных CA: проверка сертификатов
отключена осознанно, наружу ходит только статический openssl.

## Вкладка YouTube

Живёт в chroot с Debian на планшете (`chroot/yt_service.py`, :8081),
RezkaServer проксирует туда `/api/yt/*`.

* **Ленты** (подписки, рекомендации, поиск, канал) — YouTube Data API v3,
  `youtube.readonly`, OAuth2 с refresh-токеном. Токен обновляется в памяти,
  на диск не пишется.
* **Рекомендации** — отдельная история: Data API не умеет «мою ленту»,
  поэтому фид берётся через yt-dlp с куками аккаунта, а при неудаче —
  фолбэк на темы (`relatedToVideoId` + подписки).
* **Стрим** — yt-dlp отдаёт m3u8, ffmpeg склеивает в mpegts, сервис режет
  по `Range` и отдаёт прокси-ссылкой.

Свой экземпляр: создать проект в Google Cloud, включить YouTube Data API v3,
OAuth-клиент типа *Desktop*, пройти consent — получить `client_id`,
`client_secret` и `refresh_token` со scope
`https://www.googleapis.com/auth/youtube.readonly`, положить в
`/home/tema/rezka-yt/oauth.json` (права 600). В репе токенов нет и быть
не должно — файл создаётся руками на устройстве.

## Нюансы

* Ссылки на поток живут около суток (токен с датой). Протухли — сбросить
  кэш (`rm data/cache/*.json`) и запросить заново.
* Сайт отдаёт данные только после proof-of-work челленджа; обычный curl/requests
  получает 403. Оба клиента (`agent.js`, `rezka_curl.py`) решают его сами.
* Постеры приходят с отдельного CDN-хоста, который периодически ложится —
  при недоступности картинки в интерфейсе останутся пустые превью, сам
  каталог при этом работает.
* Штатный MX Player на 4.2.2 теряет query у относительных путей HLS —
  поэтому сервер переписывает манифест на абсолютные прокси-ссылки.

## Дисклеймер

Учебный проект под собственный парк древних устройств. Данные берутся из
открытых страниц сайта, никакой обход платного доступа не делается: премиум
переводы и качества отбрасываются. Использовать на свой страх и риск и с
уважением к правообладателям.
